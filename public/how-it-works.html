THE FIELD GUIDE

Read the response.

An edge cache stores a response under a cache key. The browser has its own separate cache. Our experiments distinguish the two.

MISS

Not stored here yet

The edge fetches an eligible resource from origin. Later requests may reuse it while it remains fresh.

HIT

Served from edge

The requested representation was found in cache. Compare Age and X-Origin-Served-At across reloads.

BYPASS / DYNAMIC

Not an edge hit

Policy can prevent storage. API and admin responses must remain outside shared caches.

The headers that matter

HeaderMeaning in this lab
Cache-Controlpublic, max-age=60, s-maxage=2592000: one minute browser freshness; thirty days shared-cache freshness, subject to CDN rules.
ETag / Last-ModifiedValidators support conditional requests and 304 responses. Express static ETags are weak metadata validators, not a byte hash.
AgeEstimated response age in seconds. Absence does not establish a MISS.
CF-Cache-Status / CF-RayCloudflare's observed cache state and request identifier. The Ray suffix indicates the handling data center.
X-Origin-Served-AtTimestamp attached when origin serves the response; a cached copy can retain an older timestamp.
Timing-Allow-OriginLets other origins access detailed Resource Timing values. CORS alone is insufficient.

Three ways to make a change visible

TTL: wait until freshness expires, then fetch or validate again. Purge: actively invalidate a cached key. Versioning: change the URL so a new key is requested. In this lab ?v= is a content hash; it works only if the CDN includes the query in its cache key.

For production, prefer immutable fingerprinted filenames. This demo overwrites banner.jpg; old version URLs are not archived and can return new bytes after eviction.

no-cache permits storage but requires validation before reuse. no-store tells caches not to store the response. They are different directives.
